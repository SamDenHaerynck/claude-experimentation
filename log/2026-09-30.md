## Work: Slice 2b
1. Installed the .NET 8 SDK per RUNBOOK. Checked Maven Central metadata: the latest Saxon-HE 12.x
   is 12.10, and its POM declares xmlresolver 5.3.3. Downloaded both. Saxon hit HTTP 429 once
   (96-byte text body); the retry got a real jar. SHA-1 of both matched the `.sha1` files on
   Maven Central, and I pinned their SHA-256 in the csproj.
2. `BePeppolCommerce.Core.csproj`: `IKVM` 8.16.1, and a batched MSBuild target that downloads each
   jar to `obj/jars/` if it is missing, always checks the SHA-256, and deletes the file and fails
   on a mismatch. I tested this in a clean copy with a fake 429 body in place: the first build
   failed with the mismatch message and deleted the file, and the second downloaded it and passed.
   I did not try `MavenReference` (the known PKIX failure behind the proxy).
3. `Validation/SchematronCompiler` plus `tools/RulesGen` (not in the solution) regenerate the XSLT
   with the ISO skeleton at 77dcd36. Committed `CEN-EN16931-UBL.xslt` (1.0 MB) and
   `PEPPOL-EN16931-UBL.xslt` (0.24 MB) from v3.0.20 (commit 261c458), and `SOURCE.md` with the
   licences. CEN is EUPL-1.2, the skeleton is MIT (LICENSE checked), and the Peppol file's licence
   is not stated (flagged for the owner).
4. `Validation/UblSchema`: the 15 UBL 2.1 XSDs that Invoice and CreditNote import, vendored
   unmodified from the OASIS UBL-2.1.zip, with `NOTICE.md` quoting the OASIS permission notice.
   They are embedded resources, and a resolver serves only those. Validation is serialised with a
   lock (`XmlSchemaSet` is not documented as thread-safe).
5. `Validation/PeppolValidator`: a root-element guard (Invoice or CreditNote), then XSD, CEN and
   Peppol. Each stylesheet is compiled once (`Lazy`, a new `XsltCompiler` for each), with a new
   transformer per call. Findings carry rule set, id, flag, message and location. Only `warning`
   is non-blocking. String input is parsed with `DtdProcessing.Prohibit` and a null resolver.
6. Day-026 lows: `OrderJson.Parse` now rejects null or blank required strings (with the member
   path in the message). The missing BuyerReference, DueDate/PaymentTerms and exemption reasons
   are left to the validator by design, and tests prove it reports R003, BR-CO-25 and BR-E-10.
7. Tests: 14 to 38, all passing. Upstream `rules/examples` (9 files), run locally through a
   scratch console: all valid, zero findings. They are not vendored because the upstream repo has
   no LICENSE. Latency: first call about 3 to 4 s, then about 25 ms per invoice (average of 20).
8. Found and fixed during the work: without the root guard, a non-invoice document would pass
