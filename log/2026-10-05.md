  - https://docs.recommand.eu/ is a Next.js app; its HTML links `/reference` and

  - Cloned https://github.com/brbxai/recommand-peppol (commit `cb80aeb`, 2026-10-04). `index.ts`
    serves the spec on `/openapi` and `/llms-full.txt`.
  - https://peppol.recommand.eu/openapi (and https://app.recommand.eu/openapi) return the OpenAPI
    3.1.0 spec "Recommand Peppol API", server `https://app.recommand.eu`, security `httpBasic`
    (API key and secret) or `jwt` bearer.
  - `POST /api/v1/{companyId}/send`: body `oneOf` per `documentType`; the `xml` variant takes
    `recipient` (Peppol address `scheme:id`, example `0208:987654321`), `document` (a complete UBL
    or CII string), optional `doctypeId`/`processId` (detected for raw XML). 200 returns
    `{success: true, id, sentOverPeppol, deliveryStatus, ...}`; 400 and 422 return
    `{success: false, errors: {field: [messages]}}`. No idempotency key on send (the spec's
    idempotency keys are on e-reporting submissions and webhook deliveries only).
  - `GET /api/v1/documents/{documentId}`: 200 returns `{success, document: {id, direction
    (incoming|outgoing), xml, ...}}`; 404 and 500 also listed. An unknown route returned
    `{"success":false,"errors":{"root":["Not found"]}}` (observed directly).
  - Webhooks (`POST /api/v1/webhooks`): every team event (`document.received` and others) goes to
    one URL, optionally signed with `X-Signature: sha256=<hex>` (HMAC-SHA256 of the raw body), with
    an `X-Idempotency-Key` header. The delivery body shape is not in the spec.
