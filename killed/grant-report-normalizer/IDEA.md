# Idea: Grant-report normalizer for small nonprofit program staff

## Concept
Program staff enter outcome/spend data for a grant-funded program once, in one internal format.
The tool reformats that same underlying data into each individual funder's own report template
(narrative sections, budget line items, output/outcome metrics), so staff stop manually
copy-pasting and reformatting the same numbers into 20-30 differently-shaped funder templates.

## Target user
Program/development staff at small nonprofits (roughly 1-10 program staff, no dedicated grants
database or grants-management software) who hold 40-60 active grant-funded programs across 20-30
funders, each funder requiring its own report format and timeline.

## Problem
Reformatting the same underlying program data into each funder's differing report template is
described as "one of the most time-consuming tasks for nonprofits," compounded by "a single
organization may juggle 40-60 applications and just as many unique reporting requirements from
20-30 funders, each with its own format and timeline"
([exponentphilanthropy.org](https://exponentphilanthropy.org/blog/how-to-simplify-grant-applications-and-reports-for-nonprofits/),
both quotes carried over from `BACKLOG.md`, to be independently re-verified in `VALIDATION.md`).

## Why now
No specific regulatory or platform trigger. The case rests on property (b) from the
2026-09-07 `BACKLOG.md` re-ranking (recurring workflow value: the same underlying data gets
re-formatted repeatedly as new funders and reporting cycles arrive, not a single generated
artifact) plus a genuinely undisclosed-competitor gap at the point of sourcing (Foundant and
Submittable were checked and found to be funder-side intake portals, not grantee-side
reformatting tools). `BACKLOG.md` flagged that this absence must be re-verified fresh rather than
trusted, and that nonprofit willingness-to-pay is the single biggest untested risk given typically
tight nonprofit budgets — both are the focus of `VALIDATION.md`.
